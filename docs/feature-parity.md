# Source comparison: recruiter redesign

Reviewed on 22 September 2026 against the latest fetched `sync-ngo-sy/sync-hub-v2/main`, commit **fa80ab1a7e63afbf1447cd9de92db9af6622bf94**. The source was read without modifying it.

**This redesign is not a one-for-one functional replacement for the source portal.** It is a standalone, browser-local design preview. The first version covered the major destinations and selected domain rules, but simplified several frontend capabilities as well as omitting the production integration. Matching the navigation inventory is not feature parity.

The source of this comparison is the recruiter [CONTEXT.md](https://github.com/sync-ngo-sy/sync-hub-v2/blob/fa80ab1a7e63afbf1447cd9de92db9af6622bf94/apps/recruiter-portal/CONTEXT.md), its [feature implementations](https://github.com/sync-ngo-sy/sync-hub-v2/tree/fa80ab1a7e63afbf1447cd9de92db9af6622bf94/apps/recruiter-portal/src/features), route tests, and shared rich-text components. This is a source and UI comparison, not a test against a running production backend.

## Restored or improved in this revision

- Job descriptions now use Tiptap with the source portal's Markdown interchange format. Bold, italic, three heading controls, bulleted lists and numbered lists are restored; undo/redo and active formatting feedback are also provided. As in the source editor, the H1/H2/H3 controls create document headings `h2`/`h3`/`h4`, below the page title. Formatting renders in wizard review, job detail, public opportunity preview and subsequent edits.
- Jobs, candidate search, talent pool, applications, placements and tracked links offer persistent Cards/Rows preferences. These are presentation enhancements, not a change to filtering or selection scope. Dashboard metric cards and forms are not record collections and keep their existing structure.
- Application selection uses a native checkbox with a 52px interaction area, expressive checked-state shape/color, visible keyboard focus and disabled-state feedback. The source's individual-row selection rule remains: no select-all checkbox.
- Application review is split into Overview, Profile, Assessment, Notes & tags, Messages and Activity. Candidate views have Profile, Notes & tags and Placements. Section selection is addressable through `tab`; candidate origin remains in `from`. Switching sections preserves unsent note/message text while the page remains open.

## What is safe to carry into integration

The Material tokens, responsive layouts, view controls, tab organization, rich-text components and tested local transition rules are reusable. The local store and sample models are **not** production API contracts. Integration must restore the source's typed schemas, server-owned permissions, complete readings/origins, pagination, data snapshots, capability checks and per-widget request/error behavior. Preview-only editing affordances must be reconciled with the source rules before production use.

Do not claim feature parity until the remaining frontend differences have been addressed and the source route/workflow tests have been adapted and passed against the actual APIs. A successful Pages build or a working local demo does not establish that parity.
